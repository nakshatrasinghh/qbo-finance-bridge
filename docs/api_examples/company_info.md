# CompanyInfo read-only example

**Status:** LIVE SANDBOX VALIDATED on 2026-07-15. Values below remain sanitized rather than copying the developer-owned company response.

## Local Rails action

OAuth consent requires a browser because Intuit asks the developer to sign in and select a sandbox company:

```text
http://localhost:3000/quickbooks/connections
```

Choose **Connect a QuickBooks sandbox**, approve the accounting scope, and allow Intuit to return to:

```text
http://localhost:3000/quickbooks/connections/callback
```

Rails redirects to the persisted connection page. After connection, the same read can be triggered with:

```bash
curl --fail-with-body --silent --show-error \
  http://localhost:3000/quickbooks/connections/LOCAL_CONNECTION_ID
```

Expected local HTTP status: `200`. The response is HTML containing selected CompanyInfo fields and no OAuth token or client secret.

## QuickBooks request generated by Rails

```http
GET https://sandbox-quickbooks.api.intuit.com/v3/company/REALM_ID/companyinfo/REALM_ID?minorversion=75
Accept: application/json
Authorization: Bearer [FILTERED]
```

There is no request body. `REALM_ID` comes from the validated OAuth callback and the selected `QuickbooksConnection`, never from this local GET request.

## Sanitized illustrative QuickBooks response

```json
{
  "CompanyInfo": {
    "Id": "1",
    "CompanyName": "Example Sandbox Company",
    "LegalName": "Example Sandbox Company LLC",
    "Country": "US",
    "FiscalYearStartMonth": "January",
    "SubscriptionStatus": "SUBSCRIBED",
    "DefaultTimeZone": "Pacific Standard Time"
  },
  "time": "2026-07-14T12:00:00.000-07:00"
}
```

Field presence and values depend on the selected sandbox. `CompanyInfo.Id` is the CompanyInfo entity's ID and is not the OAuth realm ID; a live sandbox returned a nonblank, one-digit entity ID while the callback realm was a different 16-digit identifier. Rails requires a CompanyInfo object with a nonblank entity ID. Realm isolation comes from the validated OAuth callback, the selected connection, and the realm-scoped request path.

## Direct readback

The CompanyInfo GET above is itself the readback. For an independent manual comparison:

1. Open the Intuit Developer API Explorer while signed in.
2. Select the same sandbox company.
3. Select **CompanyInfo** and perform its read operation.
4. Compare `CompanyName`, `Country`, fiscal-year setting, subscription status, and time zone with the Rails page. Treat `Id` as the CompanyInfo entity ID, not as the realm ID.
5. Open the sandbox QuickBooks UI and verify the company identity/settings correspond to that same sandbox.

Never paste access or refresh tokens into project documentation, issue trackers, terminal history, or screenshots.

## Expected accounting effect

None. OAuth authorization and CompanyInfo reads are non-posting infrastructure operations. They do not debit or credit an account and should not change Profit and Loss, Balance Sheet, Cash Flow, Trial Balance, General Ledger, Accounts Receivable, or Accounts Payable reports.
